# Podman

- podman-docker の `docker` は `exec podman "$@"` する薄い shim。`[source]` containers/podman@e3727b8 `docker/docker.in` (2026-07-15 確認)
- podman が remote モード (API socket に接続) になるのは `CONTAINER_HOST`/`CONTAINER_CONNECTION` 環境変数と `--remote`/`--connection`/`--url`/`--host`/`--context` フラグのみ。`DOCKER_HOST` では remote にならないため、shim 経由の `docker info` は API service 不在でも成功する (readiness check には使えない)。`[empirical]` podman 5.4.2: dead socket を指す `DOCKER_HOST` 下で `podman info` exit 0、同じ socket を `-H` 指定すると exit 125 (2026-07-15 確認)。判定コード: containers/podman@e3727b8 `cmd/podman/registry/remote.go` `IsRemote()`
- `podman compose` は外部 provider (docker-compose 等) が local Podman socket と通信できるよう環境を設定して exec する薄い wrapper。`[man]` podman-compose(1) (2026-07-15 確認)。socket の受け渡しは `DOCKER_HOST` で行われ、未設定時は default API address にフォールバックする。`[source]` containers/podman@e3727b8 `cmd/podman/compose.go` `composeDockerHost()` (2026-07-15 確認)
- rootful の default API address は `unix:///run/podman/podman.sock`、rootless は `unix://$XDG_RUNTIME_DIR/podman/podman.sock`。`podman system service` は endpoint 引数なしでそこに bind し、`--time=0` で無期限に待ち受ける。`[man]` podman-system-service(1) (2026-07-15 確認)
- `podman system service` は bind 前に stale socket file を自分で unlink するため、起動前の socket 掃除は不要。`[empirical]` podman 5.4.2: 手で置いた socket file の上から起動成功 (2026-07-15 確認)。`[source]` containers/podman@e3727b8 `cmd/podman/system/service.go` `service()`
- podman-docker は systemd 環境では tmpfiles.d で `/run/docker.sock → /run/podman/podman.sock` の symlink を張る。systemd の無いコンテナ内では socket activation とこの symlink が両方欠けるため、service 起動と symlink を手動で補う。`[source]` containers/podman@e3727b8 `contrib/systemd/system/podman-docker.conf` (2026-07-15 確認)
- rootless の runtime dir は `XDG_RUNTIME_DIR` 未設定かつ `/run/user/$UID` 不在だと `/tmp/storage-run-$UID` に解決される。socket パスは手計算せず podman 自身の既定解決 (`podman info --format '{{.Host.RemoteSocket.Path}}'`) に任せる。`[empirical]` podman 5.4.2, cc-web sandbox (2026-07-15 確認)
