## 良かったこと

- 定義域を先に閉じる順序が機能した。curl の proxy の指摘 (P1) に対し、`--noproxy` の点修正でなく、curl が読む入力の目録を先に書き、`-q` と loopback 限定の `--noproxy` で閉じ、テストは子プロセスの環境を全部握って回す形にした。
- 実装 subagent が指示を実測で覆した。「`--noproxy` を無条件で渡す」という指示に対し、`--noproxy` が `NO_PROXY` を置き換えることを実測し、127.0.0.1 宛てだけに限る形にしてテストで固定した。指示より契約を優先する動きが望ましい。
- 観点の問いに対して反証する規則 (救済案でなく主張を反証する) で、コメント担当の誤指摘を機械的に却下できた。
- 計画に「未実測」を明記していたので、前提 (自動再開) が崩れたときの修正が計画の 1 行と実装の文言だけで済んだ。
- ローカルレビューと Codex は違う種類を拾った。ローカル (資源の解放・事前検査・定義域) は codex-limits.sh の trap の順序、冗長な事前検査、jq の失敗の握りつぶしを拾い、Codex は定義域の端 (同じ秒の時刻、worktree、config の scope) を拾った。両方要る。
- hook を common git dir に写す形にした後、Codex は同じ箇所に指摘を出さなくなった。定義域が設定に依存しない機構に閉じると反復は止まる。

## 手順と環境

- 実測できなかったもの: codex-limits.sh の成功経路 (sandbox 内では codex の HTTP client が proxy を越えられない)。同じ秒の時刻の重なりも実物では未観測 (schema と形式からの推定)。次の実際の上限で実測する。
- sandbox で書けなかった場所と回避: canon (作業ディレクトリに追加してもらった)、`.git/config` と `.git/hooks` (sandbox を外して 1 回ずつ)、`.claude/skills` (ユーザーが直した)、`.git/worktrees` (対象を指定した target-diff.sh が使えない。指定無しで回した)。セッションの最初に、書く必要のある場所を一覧にして確かめておくと途中の足止めが減る。
- haiku のコメント担当は、テストの fake の先頭コメントと model の制約を 3 件とも誤指摘した。テストの fake の先頭は「スクリプトの先頭」(契約) として扱う、と観点の判定例に足す余地がある。
- 1 ラウンドの費用: 実装か修正の subagent 1 体 (Opus、10〜45 分) + レビュー 4〜7 体 (2〜8 分) + verify.sh 3〜4 分。Codex は push から 5〜15 分で返す。

## 残っていること

- 上限の reset 経路の実測 (上記)。
- Codex の 22 ラウンドの指摘のうち、findings.md に書いたのは hooksPath の系列だけ。手順は変えたが、過去の分は遡って書いていない。
- verify.sh の hook の写しは、追跡ファイルへの symlink に置き換えられても検査を通る。verify.sh しか書かない前提で放置している。
- 相対の `core.hooksPath` が `.git/hooks` なら main worktree での verify.sh は通るが、linked worktree では hook が別の場所になる。その worktree で verify.sh を回せば検出される。
