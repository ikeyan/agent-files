ある要素を消したとき、離れた場所のコード・コメント・テストが壊れないか。

検出手順: diff 内の break / continue / 早期 return / 状態フラグ / 条件付き代入を全て列挙し、それぞれ「これを消したとき、離れた場所 (別のループ・別の分岐・別の関数・コメント・テスト) の前提が壊れるか」を答える。壊れるなら、その 2 箇所の意味論を 1 箇所にまとめる案を出す。
- 互いに相関する変数 (`let aborting: boolean` と `abortCode: number`) は、不正な組み合わせを表せない 1 つの変数にまとめる。
- 同じ判定 (「この環境はどれか」「この入力は対象か」) が複数箇所にあれば、1 箇所で判定して結果を渡す。
- コメントは、各コメントが説明している行範囲を特定し、直下の範囲と一致しない部分 (別の分岐・別の要素・関連説明) を切り出して、その対象の近くか 1 箇所 (ファイル先頭・独立したドキュメント) に移す。
匂い: ネストループ内の break、複数の分岐が同じ変数を読む、「それ以外は」「anything else」「otherwise」を含むコメント、Set / 配列 / オブジェクトの宣言の直上にある 2 行以上のコメント、`—` や `;` の後に置かれた句。
