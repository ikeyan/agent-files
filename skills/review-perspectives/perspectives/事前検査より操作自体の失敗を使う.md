操作の前に「できるか」を別途検査していないか。操作自体が失敗を返すなら、その失敗だけで判定する。

検出手順: exists / has / includes / typeof などの確認の直後に、その対象への操作 (read / get / call) が続く箇所を列挙する。操作自体が失敗 (例外・undefined) を返すなら、確認を削って操作の失敗で判定する案を出す。
匂い: existsSync の直後の readFileSync、has の直後の get、`if (x) x.y`、probe / プローブ / 事前に起動して確かめる / 「動くか試してから使う」— 本番の操作 (起動、接続、読込) を別途先に試す関数。
判定規則: 事前検査 (プローブ、バージョン検査、存在確認) が見つかったら、それを速くする・非同期にする・別の代理指標に替える提案は解ではない (どれも事前検査のまま)。解は「候補を列挙し、本番の操作をそのまま試し、失敗したら次の候補へ進む」構造で、成功時のコストがゼロになる。指摘にはその構造への書き換え案を添える。
