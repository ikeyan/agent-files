diff が変えた振る舞いを、失敗しうるテストか検査が固定しているか。

検出手順: diff が追加・変更した振る舞い (分岐、エラー経路、既定値、出力の形、走査や優先の順序) を全て列挙し、各々について、その振る舞いを元に戻したら失敗するテスト・検査を引用する。引用できなければ指摘する。diff が削除・緩和したテストは、固定していたケースを書き出し、別のテストが引き継いでいるかを答える。
匂い: テストの無い新しい分岐, 削除された test / it, `skip` / `only` / 緩められた assert, 期待値を実装に合わせて書き換えただけのテスト変更, 指摘の 1 点を写しただけの fixture, 同じ引数に対する N 個目の例
判定規則: 「手で確かめた」は是認理由にならない。入力が自由な文字列 (パス・ref 名・環境変数の値・HTTP 応答・ファイル名) か外部システムの状態 (git の履歴・リモートの API の状態) なら、1 点ずつの fixture も是認理由にならない。認めるのは、仕様で有限集合に狭めた上での列挙か、目録 (canon の `facts/<topic>/`) の次元ごとに値を生成する property based / model based test のどちらか。テストにできない実行時契約 (権限、環境変数の有無、orchestrator) は、実測の記録が PR 説明・コミット本文にあれば足りる。
