規則を述べる文が、採る規則を 1 回述べるだけになっているか。

検出手順: diff で追加・変更された箇条書きの項目・文を全て列挙し、各項目 I について次を行う。
1. R := I が読者に求める行動を、肯定形の 1 節 (「〜で決める」「〜する」) で書いたもの (採る規則)。X := R が値を決める対象。V := R が X に与える値。
2. I の節のうち R 以外を全て列挙し、各節 S について次を順に判定して、最初に当てはまった分類にする。
   1. S が真偽を持つ事実を述べる (「〜は〜する」「〜は読めない」「〜が付く」): C := S の命題。「C が偽なら、R は別の規則になるか」を答える。
      - なる: 前提。1 文の事実として残す。外部依存の事実なら canon に置いて参照にする。
      - ならない: 事情。
   2. S が、S の文字列にある句を否定して退けている (形の例: 「〜でなく」「〜ではなく」「〜せず」「〜は使わない」「〜では決めない」「〜でも」、"not … but"、"instead of"、"rather than"、"do not … ; …"): W := 退けられている句。S の文字列から取り、S に無い句や否定を補わない。「X を V にしたまま W にもできるか」を答える。
      - できない: 代案の否定。
      - できる: W をしないことは独立した規則。
   3. S が R を別の場面に当てはめ直しただけ: 帰結。
   4. S が命題にできない (「試した」「最初は」「〜の指摘」、出典): 事情。
   5. S がそれ以外の行動を求める: 独立した規則。
3. 代案の否定・帰結・事情に分類した S を全て削った I を、書き換え案として出す。削る S があれば 1 件の指摘にする。
匂い: でなく, ではなく, せず, 使わない, では決めない, でも, のためと, 前提で, not … but, instead of, rather than, regardless of, even if, 否定や帰結の後に続く括弧書き
判定規則:
- S が、V と対にならない行為をしないこと自体で制約を守る (「トークンを引数に載せない」) なら、独立した規則。
- 指摘の「箇所」には S を引用する。R・X・V・W・C は判定のために書き出したもので、引用と区別して示す。
- W を括弧書きに言い換えること (「V (W ではない)」)、理由を足すこと、帰結の S を残すことは解ではない。
例:
- 「全周の再構築でなく変更点に絞ったプローブでよい」: X = 検証の範囲、V = 変更点に絞る、W = 全周の再構築。X を V にしたまま W にはできないので、「全周の再構築でなく」は代案の否定。
- 「JSON を使わず YAML を使う」: X = 設定の形式、V = YAML、W = JSON。X を V にしたまま W にはできないので、「JSON を使わず」は代案の否定。
- 「書くこと: テストの目的 (手順ではなく)」: X = テストについて書くこと、V = 目的、W = 手順。両方を書けるので、「手順は書かない」は独立した規則。
- 「書くかどうかは実行者が誤った行動をするかで決める (cc-web でも canon を足せば読める)」: 括弧書きは事実を述べるので 2 の 1 に当たる。C = cc-web で canon を読める。偽でも R は変わらないので事情。
- 「検証は sonnet に渡す。haiku は誤った候補の主張をそのまま確定にする」: C = haiku は誤った候補を確定にする。偽なら haiku で足りて R が変わるので前提。
- 「PR の振り返りは merge の前にその PR に入れる。close する PR は別の PR で残す」の後の文: S の文字列に否定された句が無いので 2 の 2 に当たらない。R と別の対象 (close する PR) への行動を求めるので、独立した規則。
