相手に本文を送り、その本文上の位置で応答 (編集・診断) を受け取る設計では、送った本文をこちらでも保持し、応答をそれに適用しているか。

検出手順: (a) 位置付きの変更 (range / offset / version を持つ edit) を本文に適用している行を全て列挙し、各行について適用先の本文の出所 (readFile / 保持しているバッファ / 引数) を書く。(b) 本文を text 引数で受け取って相手に送る関数 (open / update / didOpen / didChange など) を全て列挙する。(c) (a) に出所が readFile の行があり (b) が空でなければ、その行を必ず指摘にする: 相手は (b) で送られた本文の上で位置を計算しているが、適用先はディスクの本文で、両者が同じである保証はコード上に無い (呼び出し元がディスクから読んで open していても保証ではない)。
匂い: 写しの存在 (open / registered) だけを Set で記録し送った本文を保持していない、range 付きの編集を readFile した本文に適用する、本文を text 引数で受け取る open / update と同じ対象の readFile が共存する。
判定規則: 「呼び出し元は常に保存してから呼ぶ」「現状の呼び出し元では乖離しない」は是認理由にならない (公開 API の契約ではない)。「書き込んだ内容を戻り値で返して再読込を避ける」は解ではない (適用先が readFile のままなら位置の基準は直らない)。ディスクを無条件に正本と見なさない: 相手が位置を計算した写しが適用先であり、送った本文を保持していないこと自体が指摘対象。解は、送った本文を保持してそれを適用先にし、ディスクを起点にするのは送っていない対象だけにする。指摘には、乖離する具体的な操作列を 1 つ添える。
