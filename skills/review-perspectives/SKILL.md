# 観点ごとのレビュー

[perspectives/](perspectives/) の観点ファイルを、下の表の担当ごとに別のレビュアーエージェントへ渡して diff をレビューさせ、指摘を検証してまとめる。

## 担当

1 行が 1 エージェント。観点は 1 つの担当に複数入れてよく、同じ観点を複数の担当に入れてもよい。

| 担当 | モデル | 観点 |
| --- | --- | --- |
| 代案の否定 | haiku | 代案の否定を書かない |
| インターフェース | haiku | インターフェースの使い心地 |
| 冗長性 | haiku | コメントに書いてよい内容, 他から得られるものを重ねない, 冗長な言い回し, 重複に名前を付ける |
| 簡素化 | haiku | 削減は連鎖する, 合成キーは関数従属で次元を落とす, 冪等操作にガードを付けない, 獲得と解放はスコープで対にする, 基盤ツールの失敗はそのまま見せる |
| 自然言語 | haiku | ハードラップしない, 論理構造を散文に埋め込まない, 読者を想定して書く |

- 代案の否定を書かない は単独の担当にする。他の観点と同じエージェントに渡すと、haiku は指摘しないか一部だけを削る。
- 担当を変えたら、変更前に指摘できていた diff で同じ指摘が出ることを確かめる。

## 手順

1. レビュー対象の diff をファイルに書き出す。既定は、上流より先のコミットと未コミットの変更 (`git diff @{upstream}` 相当)。
2. 表の各行について、そのモデルのエージェントを並列に起動し、次のプロンプトを渡す。`<観点ファイル>` はこのスキルの `perspectives/<観点>.md` の絶対パス。

   ```text
   あなたはコードレビュアーです。次のファイルだけを Read ツールで読み、他のファイル・リポジトリ・git は一切読まないでください。
   - レビュー観点: <観点ファイル> (1 行に 1 つ)
   - レビュー対象の diff: <diff ファイル>

   diff の追加行 (+ 行) を、レビュー観点に照らしてレビューしてください。指摘ごとに「箇所 (ファイルと該当部分の引用)」「どの観点に、なぜ違反するか」「書き換え後の文」を書いてください。指摘が無ければ「指摘なし」。
   ```

3. 全ての担当の結果を集め、各指摘を現在のファイルで確かめる。観点に照らして成り立たない指摘は理由を添えて落とす。
4. 同じ箇所への指摘をまとめる。削る指摘と書き換える指摘が重なったら、削った後の文に書き換えを当てた 1 つの案にする。
5. まとめた指摘を報告する。

## 観点ファイルの型

```text
<問い>                  1〜3 文。何を確かめるか。

検出手順: <diff 上で何を全部列挙し、各項目に何を問うか>
匂い: <grep できる兆候をカンマ区切り>
判定規則: <誤った是認・誤った解を排除する規則>   任意
```
